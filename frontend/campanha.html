Antes vs Depois: Código Real

Veja como pequenas mudanças no código tornam a experiência acessível para todos.

Inacessível Botão sem contexto

<div onclick="comprar()">
  <img src="cart.png">
</div>

Sem role, sem texto alternativo, não focável por teclado, leitor de tela ignora.

Acessível Botão semântico

<button onclick="comprar()" 
        aria-label="Adicionar ao carrinho">
  <img src="cart.png" alt="">
  <span class="sr-only">Adicionar</span>
</button>

Elemento semântico, focável, com texto para leitores de tela.

Inacessível Input sem label

<input type="text" 
       placeholder="Nome">

Placeholder desaparece ao digitar. Leitor de tela não sabe o que o campo pede.

Acessível Input com label

<label for="nome">Nome completo</label>
<input type="text" id="nome" 
       autocomplete="name">

Label visível e associado. Leitor anuncia "Nome completo, campo de texto".

Inacessível Imagem sem alt

<img src="produto.jpg">

Leitor de tela lê o nome do arquivo: "produto-ponto-jpg".

Acessível Imagem descritiva

<img src="produto.jpg" 
     alt="Action figure Guerreiro Estelar 
     com armadura prateada e espada 
     de energia azul">

Descrição rica que permite ao usuário imaginar o produto.

Ferramentas de Teste

Use estas ferramentas para descobrir falhas no seu código:

Google Lighthouse

Auditoria automática integrada ao Chrome DevTools. Gera score de 0 a 100 para acessibilidade.

Detecta: contraste, alt text, labels, landmarks, heading order.

Documentação oficial →

axe DevTools

Extensão para Chrome/Firefox que encontra falhas que o Lighthouse não detecta.

Detecta: ARIA inválidos, tabindex errado, formulários sem fieldset.

Baixar extensão →

WAVE

Ferramenta visual que mostra erros diretamente na página com ícones coloridos.

Detecta: estrutura de headings, links vazios, tabelas sem cabeçalho.

Testar online →

NVDA (Leitor de Tela)

Leitor de tela gratuito para Windows. Simula a experiência de um usuário cego.

Detecta: problemas que nenhuma ferramenta automática pega (fluxo, contexto).

Download gratuito →

Comece Agora

Acessibilidade não é feature — é requisito. Cada linha de código que você escreve pode incluir ou excluir milhões de pessoas.

  1. Abra o DevTools (F12) → aba Lighthouse → marque "Accessibility" → gere o relatório
  2. Instale o axe DevTools e rode no seu projeto
  3. Navegue seu site inteiro usando só o teclado (Tab + Enter). Funcionou?
  4. Ative o VoiceOver (Cmd+F5 no Mac) e ouça como seu site é lido
